# 设计参数映射与编码技能

## 适用场景

用于把用户口述的中文参数、零部件术语、别名、部位描述或旧参数名，映射到标准参数 ID、NX 表达式名、模板字段或参数编码候选。

## 与 design-data-query 的关系

本技能负责“参数语义消歧和编码决策”；`design-data-query` 负责“数据库查询路线和 SQL 模板”。需要查询参数词典、历史模板记录、文档模板、编码类型表、schema 或唯一性验证时，应先加载 `design-data-query`，再通过 `mysql_query` 执行对应 SQL。参数化建模所需的数模模板不走 MySQL 主路径，必须加载 `teamcenter-flow` 从 TC `智能体模板库` 查询。不要恢复多个 MySQL 工具名，也不要绕开 `mysql_query`。

## Beya 使用边界

Beya 只保留一个数据库工具入口：`mysql_query`。参数词典、历史模板记录、编码类型表、唯一性验证和必要写入都通过 SQL 表达，而不是拆成多个数据库工具；数模模板的真实可用性以 TC `智能体模板库` 查询和 NX 打开结果为准。

`mysql_query` 是可用时的标准检索入口，不是失败后可以被默认假设替代的“软步骤”。如果数据库不可用、SQL 执行失败、查询为空且没有其它明确资料依据，本轮参数映射状态必须是“未完成/被阻断”，不得把经验默认值、常规尺寸或模型猜测标记为已完成参数映射。

## 数据来源顺序

1. 用户输入：抽取用户已明确给出的零部件、机型、部位、参数名、数值、单位和约束。
2. 已加载 workspace 资料：只有读取到明确文件内容或结构化表格内容时，才能作为参数映射依据；不能因为某个目录或文件名存在就声称已命中。
3. `mysql_query`：需要参数词典、历史模板记录、编码类型表或唯一性验证时使用。输出必须包含 `query_result` 与 `sql_statement`。
4. 用户确认：如果只能形成候选草案，必须标注“未验证/待确认”，不能进入写库、NX 修改或任务完成状态。

## 推荐 SQL 路线

1. 查询现有参数候选：优先查 `nx_param_dic_cn_v2`，按中文名称、同义词、标准 ID、零部件、部位、语义等字段模糊匹配。
2. 查询历史模板记录：零部件历史模板记录可查 `part_template_table`；设计文档模板查 `doc_template_table`。需要实际数模模板时，转入 `teamcenter-flow` 查询 TC `智能体模板库`。
3. 生成新编码时，读取 `parameter_code_types` 中的 `part_code`、`section_code`、`semantic_code`，组合为 `<part_code>_<section_code><semantic_code>` 或既有规则要求的标准格式。
4. 唯一性验证：写入新编码前必须查询目标表是否已存在相同 `std_id`。
5. 写入数据库：只有用户明确确认“新增/保存编码或类型”后才允许执行 INSERT/UPDATE。

## 完成判定

只有满足以下任一条件，才可以说“参数映射完成”：

- `mysql_query` 成功返回了可用候选，并且候选已被用户确认或任务只要求查询展示；
- workspace 中的明确资料内容已经被读取并给出可追溯依据；
- 用户直接给出了完整且明确的标准参数 ID / NX 表达式名 / 编码，并确认可使用。

以下情况必须说“未完成”或“需要确认”：

- 数据库连接失败、SQL 报错或结果为空；
- 只根据常规经验给出尺寸、材料或编码猜测；
- 未读取到参数词典、必要历史记录、TC `智能体模板库` 模板候选或用户确认；
- 后续 NX/TC/报告动作依赖该参数映射结果。

## 输出要求

给用户展示候选参数、匹配依据、验证状态、是否需要确认、新编码草案和下一步动作。不要暴露数据库连接信息。未完成时不要使用“已完成、已生成、已设置好”等完成态表述。
