零部件设计智能体示意图 PPT 大纲

用途：
用于向画图人员说明两张核心示意图的内容、重点和布局要求。
整体目标不是画完整软件架构，而是展示零部件设计智能体如何通过 LLM、skill、工具和业务资料完成参数化设计与优化求解。


============================================================
第 1 页：汇报定位
============================================================

建议标题：
零部件设计智能体：从业务经验到参数化优化设计

核心表达：
零部件设计智能体不是简单问答工具，而是通过 LLM + skill + 工具 + 业务资料，把设计经验、经验公式、NX 表达式、DFMEA 风险规则和设计规范转化为可执行的参数化设计过程。

页面内容：

1. 业务背景
- 零部件设计依赖大量经验公式、历史模板、设计规范、DFMEA 风险规则。
- 设计经验分散在公式表、NX 表达式、DFMEA、P 图、边界图、设计说明书等资料中。
- 人工设计流程中，参数计算、模板选择、风险校核、出图和文档生成耗时长。

2. 智能体目标
- 理解用户或业务系统中的设计任务。
- 调用 skill 获取业务知识。
- 调用工具解析公式、风险、模板和规范。
- 构造优化问题并求解。
- 输出 NX 参数化模型、二维图纸、设计说明书、参数属性表和 DFMEA 风险依据。

3. 本次需要展示的两张核心图
- 图 1：零部件设计智能体机制架构示例。
- 图 2：零部件设计智能体运行示例。

建议画面：
左侧展示人工设计痛点，右侧展示智能体能力闭环。
底部明确两张图的定位：
- 图 1 讲智能体机制骨架。
- 图 2 讲一次具体运行过程。

第 2 页：图 1 总体定位
============================================================

建议标题：
图 1：零部件设计智能体机制架构示例

核心表达：
图 1 的主体是“零部件设计智能体机制骨架”，不是完整软件架构图，也不是知识图谱图。

图 1 要表达：
LLM 调度 -> Skill 路由 -> 工具调用 -> 资料读取 -> 上下文回填 -> 执行生成

图 1 关注的问题：
- skill 在智能体架构中起什么作用？
- skill 如何被 LLM 调度和路由？
- skill 如何调用工具？
- 工具如何读取业务资料？
- 资料如何变成设计任务中的中间结果？
- 中间结果如何回填到“运行中的设计上下文”？
- 上下文如何进入后续优化建模与工程生成？

图 1 不应该画成：
- 完整软件架构图。
- 数据库架构图。
- 知识图谱图。
- 普通流程图。

图 1 应该画成：
- 智能体机制骨架图。
- 带一个业务例子的 skill / 工具 / 资料调用网络示例。

推荐主视觉骨架：

用户任务 / 业务系统任务
        |

        |
        v
Skill 路由 / 编排
        |
        v
运行中的设计上下文
        |
        v
多个 skill 围绕上下文读写
        |
        v
skill 调用工具
        |
        v
工具读取业务资料
        |

中间结果回填上下文

skill 向下调用工具，工具再连接公式表、NX 表达式、DFMEA、P 图、边界图、规范等资料。

============================================================
第 3 页：图 1 详细内容
============================================================

建议标题：
图 1 细化：Skill / 工具 / 资料调用网络示例

建议业务例子：
连杆参数化设计 / 连杆优化设计

图中主体元素：

1. LLM 任务理解与调度层
职责：
- 识别任务类型：参数化设计、优化设计、查询、报告生成。
- 抽取业务目标：轻量化、安全裕度、装配间隙、风险防错、输出物。
- 判断缺失信息：边界参数、发动机参数、约束条件。
- 决定调用哪些 skill，并组织调用顺序。
- 对结果进行解释和权衡。

2. Skill 路由 / 编排层
职责：
- 判断哪个 skill 先执行。
- 判断当前 skill 需要调用哪些工具。
- 判断上一步结果应该给哪个 skill 使用。
- 维护运行中的设计上下文。

3. 运行中的设计上下文
这是图 1 的核心骨架节点，不是知识图谱，也不是数据库。
它表示智能体在一次任务运行中不断更新的业务状态。

建议内容：
- part = 连杆
- intent = 参数化设计 / 优化
- known_params = 已知参数
- missing_params = 缺失参数
- selected_template = 已选模板
- formulas = 变量依赖表
- constraints = 风险约束清单
- optimization_problem = 待构造
- solver_config = 求解器配置
- deliverables = 输出物清单

4. Skill 列表与产出

需求解析 skill：
- 输入：用户任务、业务系统任务。
- 输出：任务结构化对象、已知参数清单、缺失参数清单。

资料检索 skill：
- 调用：规范检索工具、设计说明书检索工具、TC 历史模板查询工具。
- 读取：设计规范、设计说明书、历史零件模板。
- 输出：相关规范片段、候选模板、历史方案。

模板推荐 skill：
- 输入：任务结构化对象 + 候选模板。
- 输出：推荐模板、相似度依据、用户待确认项。

公式解析 skill：
- 调用：经验公式表解析工具、NX 表达式读取工具、模板公式读取工具。
- 读取：100+ 经验公式表、约 370 条 NX 表达式、模板公式。
- 输出：变量依赖表、公式计算链、可优化变量候选。

风险审查 skill：
- 调用：DFMEA 表解析工具、P 图 / 边界图解析工具、规范校核工具。
- 读取：200+ DFMEA 风险规则、P 图、边界图、设计规范条款。
- 输出：风险防错项、约束清单、证据来源。

优化建模 skill：
- 输入：变量依赖表 + 约束清单 + 设计目标 + 模板参数。
- 输出：优化问题定义、变量上下限、求解器配置。

执行生成 skill：
- 调用：优化器、NX 自动化工具、报告工具、出图工具、TC 回写工具。
- 输出：最优参数、备选方案、NX 模型、二维图纸、设计说明书、参数属性表、DFMEA 更新依据。

5. 需要视觉上突出的业务资料
- 100+ 经验公式表。
- NX 表达式约 370 条。
- DFMEA 风险规则 200+。
- P 图 / 边界图。
- 设计规范。
- 设计说明书。
- 历史模板。

图 1 的一句话要求：
零部件设计智能体通过 LLM 调度、skill 编排和工具调用，把业务资料转化为运行中的设计上下文，再逐步形成可求解、可执行、可追溯的设计任务。


============================================================
第 4 页：图 2 总体定位
============================================================

建议标题：
图 2：零部件设计智能体运行示例

核心表达：
图 2 是一次具体运行示例，展示智能体如何使用图 1 中的 skill 和工具，获取业务知识，构造优化问题，并完成优化求解和工程输出。

图 2 的主轴：
任务输入 -> skill 获取业务知识 -> LLM 收敛问题 -> 构造优化问题 -> 优化器求解 -> NX 建模 / 出图 / 报告 / 回写

图 2 的中心必须是：
优化问题构造与求解

它不应该只是流程中的一个小框，而应该是整张图最大的视觉核心。

推荐三段式布局：

左侧：知识获取与问题收敛
- 用户 / 业务系统输入。
- 需求解析 skill。
- 资料检索 skill。
- 模板推荐 skill。
- 公式解析 skill。
- 风险审查 skill。
- LLM 追问缺参、缩小变量范围。

中间：优化问题构造与求解核心
- 设计变量 x。
- 固定参数 p。
- 目标函数 F(x,p)。
- 约束条件 C(x,p)。
- 优化器配置。
- 迭代求解过程。
- 最优方案 / 备选方案。

右侧：工程生成与业务回写
- NX 参数化模型。
- 二维图纸 / 自动标注。
- 设计说明书。
- 关键参数属性表。
- DFMEA 风险清单更新。
- TC 发布 / 升版。

底部：人机评审反馈闭环
- 参数缺失 -> LLM 追问。
- 方案不可行 -> skill 返回违反的约束或风险项。
- 用户不满意 -> 调整目标权重或变量范围。
- 方案通过 -> 生成设计包并回写业务系统。


============================================================
第 5 页：图 2 详细内容
============================================================

建议标题：
图 2 细化：业务知识如何转化为优化问题

示例输入：
用户或业务系统提出：
请为 Kxx 机型设计或优化连杆，目标是在满足安全系数和面压约束下尽量轻量化。

1. 任务输入
- 机型：Kxx。
- 零件：连杆。
- 任务：参数化设计 / 优化。
- 已知参数：行程、缸径、曲柄半径等。
- 缺失参数：机体高度、压缩余隙、活塞压缩高度等。
- 输出要求：NX 模型、二维图纸、设计说明书、参数表。

2. LLM 理解任务
- 判断任务类型：优化设计。
- 识别目标：轻量化 + 安全裕度。
- 识别输出物：模型、图纸、报告。
- 决定调用 skill 序列。

3. skill 获取业务知识

需求解析 skill：
- 输出已知参数、缺失参数、输出物要求。

资料检索 + 模板推荐 skill：
- 调用设计规范检索。
- 调用设计说明书检索。
- 调用历史模板检索。
- 调用 DFMEA / P 图检索。
- 输出推荐模板、相关规范、风险条目、约束来源。

公式解析 skill：
- 调用 100+ 经验公式表。
- 调用 NX 表达式约 370 条。
- 调用模板公式。
- 输出变量依赖表、公式计算链。

LLM 引导问题收敛：
- 追问缺失参数。
- 固定低敏变量。
- 缩小变量上下限。
- 解释优化目标取舍。

4. 优化问题构造

输入 1：变量与公式
- 连杆中心距。
- 大头直径。
- 小头直径。
- 杆身厚度。
- 腹板厚度。
- 圆角半径。
- 公式依赖关系。

输入 2：约束与风险
- 安全系数 >= 1.2。
- 衬套面压 < 140 MPa。
- 运动轨迹间隙 >= 5 mm。
- 螺栓覆盖系数 >= 2。
- DFMEA 高风险项不得触发。

输入 3：优化目标
- 轻量化。
- 安全裕度最大化。
- 变形 / 间隙裕度最大化。
- 加工成本或通用性约束。

5. 优化建模 skill 输出
- 设计变量 x。
- 固定参数 p。
- 目标函数 F(x,p)。
- 约束条件 C(x,p)。
- 变量上下限。
- 风险惩罚项或硬约束。

6. 优化器配置
- 算法：遗传算法、贝叶斯优化、网格搜索或其他优化器。
- 初值：来自模板。
- 变量上下限：来自公式、规范和用户确认。
- 目标权重：由用户和 LLM 辅助设定。
- 约束优先级：DFMEA 高风险优先。
- 终止条件：迭代次数、收敛阈值。

7. 优化求解过程
- 生成候选参数。
- 调用公式计算。
- 调用校核脚本。
- 检查规范约束。
- 检查 DFMEA 风险。
- 过滤不可行解。
- 记录迭代过程。
- 输出最优方案和备选方案。

8. LLM 解释优化结果
- 为什么这个方案最优。
- 满足哪些约束。
- 规避哪些 DFMEA 风险。
- 哪些目标之间存在取舍。
- 用户是否需要调整权重或补充约束。

9. 工程工具执行
- NX 自动化工具：更新表达式、重建参数化模型。
- 出图工具：生成二维图纸、自动标注尺寸和检查项。
- 报告工具：生成设计说明书、关键参数属性表、优化依据说明。
- DFMEA 工具：更新风险依据和防错项。
- TC 工具：发布、升版、沉淀模板。

图 2 的一句话要求：
智能体不是直接生成设计结果，而是通过 skill 和工具获取业务知识，把业务知识转化为变量、目标、约束和求解器配置，再由优化算法求解，最后调用 NX 和报告工具生成工程交付物。
