# 设计系统规范：技术工坊

## 1. 概览与创意北极星
### 创意北极星：“数字档案员”
这套设计系统避开开发者工具常见的冷感、高科技审美，转而借鉴高端编辑设计与建筑制图空间：专注、有触感、经得起长期使用。我们要构建的是一种“数字档案员”体验：工作区像一本昂贵的亚麻封面笔记本，也像一间光线良好的工作室。

通过有意的不对称、充足留白，以及对传统盒式布局的克制，界面为深度工作提供舞台。它不争抢注意力，而是退到背景里，为开发者的代码提供沉稳、可信的承载面。

---

## 2. 色彩与表面哲学
调色板建立在 “Warm Paper” (`#FAF9F5`) 和 “Dark Graphite” (`#141413`) 之上。这个高对比但偏暖的基础色能降低长时间编码时的视觉疲劳。

### “无线条”规则
结构分区禁止依赖传统 `1px` 边框。区分功能区域（例如侧边栏与代码编辑区）时，应使用背景色层级变化。
- **应用方式：** 将 `surface_container_low` 侧边栏直接放在 `surface` 主内容区旁。4% 的色调差已经足够让人眼感知边界，同时不会制造视觉噪音。

### 表面层级与嵌套
把 UI 当作纸张和玻璃的实体堆叠。
- **基础层：** `surface` (#FAF9F5) - 桌面。
- **次级面板：** `surface_container_low` (#F4F4F0) - 内嵌工具区。
- **浮动元素：** `surface_container_lowest` (#FFFFFF) - 活跃卡片或 Modal。
- **嵌套：** 嵌套时始终上移或下移一个层级。卡片（`surface_container_lowest`）不应放在同色背景上；它应放在 `surface_container_low` 上，形成自然的抬起感。

### 玻璃拟态与色调深度
浮动工具（例如命令面板或 hover popover）使用 85% 透明度的 `surface_container_lowest`，并加 `20px` 背景模糊。这样能让底层代码和暖纸质感微微透出，保持空间感。

## 3. 字体：编辑式权威感
字体系统用 **Manrope** 承载高层结构的现代清晰感，用 **Inter** 承载数据密集任务的功能精度。

* **展示与标题（Manrope）：** 这些是“路标”。空状态使用 `display-md`，主要模块标题使用 `headline-sm`。Manrope 略宽的字距会带来昂贵、编辑式的气质。
* **正文与标签（Inter）：** Inter 是工作主力。标准 UI 文本使用 `body-md`。它针对屏幕阅读优化，也接近高端 macOS 应用的原生感。
* **代码（Monospace）：** 终端输出和代码块使用高质量等宽字体（SF Mono 或 JetBrains Mono），字号为 `0.875rem`，与 `body-md` 保持视觉重量一致。

---

## 4. 抬升与深度
我们拒绝 Web 默认的“投影即层级”。深度是一种氛围，而不是结构拐杖。

* **层叠原则：** 静态组件避免阴影，使用 `surface-container` 层级建立结构。
* **环境阴影：** 活跃浮动状态（Modal）使用多层阴影：
    * `box-shadow: 0 4px 20px rgba(27, 28, 26, 0.04), 0 12px 40px rgba(27, 28, 26, 0.08);`
    * 阴影颜色来自 `on_surface`，让它像暖纸上自然遮挡出的光影。
* **幽灵边框：** 当可访问性需要容器边界时，使用 20% 透明度的 `outline_variant`。它应被感知，而不是被看见。

## 5. 组件

### 按钮
- **主按钮：** `primary` (#8F482F) 背景，`on_primary` (#FFFFFF) 文本。
- **次按钮：** `surface_container_high` 背景，无边框。
- **标志性样式：** 使用 `radius-DEFAULT` (8px)。主按钮从 `primary` 到 `primary_container` 叠加轻微纵向线性渐变，让按钮有类似“压印油墨”的实体感。

### 聊天输入框
- **样式：** 大号 `radius-xl` (16px) 圆角。
- **背景：** `surface_container_lowest` (#FFFFFF)。
- **边界：** 不使用厚重边框，而用 15% 透明度的 `outline_variant` 做 `1px` “幽灵边框”。聚焦时只把透明度提高到 40%，不要使用发光效果。

### Chip 与状态
- **成功：** `tertiary_container` (#677B4E) 背景，`on_tertiary_container` 文本。
- **运行/警告：** `primary_fixed` (#FFDBD0) 背景，`on_primary_fixed` 文本。
- **形状：** 使用 `radius-full`，形成柔和的胶囊形，与代码网格的结构感形成对比。

### 卡片与列表
- **无分割线规则：** 明确禁止在列表项之间使用横线。用 `8px` 垂直间距或 hover 时切换到 `surface_container_highest` 背景来区分项目。
- **嵌套：** 卡片使用 `radius-lg` (12px)，并放置在 `surface_container_low` 上，以获得最佳可读性。

### 终端与代码块
- **容器：** 使用 `surface_dim` (#DBDAD6)，形成内凹感。
- **文本：** 标准输出使用 `on_surface`，链接和权限相关文本使用 `secondary` (#2D628F)。

## 6. Do 与 Don’t

### Do
- **拥抱不对称：** 主操作右对齐，但让 logo 或状态指示等“品牌瞬间”有意偏移，避免 Bootstrap 式的模板感。
- **把“温度”当工具：** `primary`（Antique Brass）只少量使用。它应该强调意图，而不是装饰界面。
- **优先留白：** 如果布局显得拥挤，先增加间距，而不是添加边框。

### Don’t
- **不要使用纯黑：** 永远不要用 `#000000`。使用 `on_background` (#1B1C1A)，保持“纸上墨迹”的柔和感。
- **不要使用尖角：** 避免 `0px` 或 `2px` 圆角。它们在这个语境里会显得临床化且缺少设计感。
- **不要使用游戏化效果：** 避免霓虹光、重度模糊和高饱和蓝色。如果它看起来像宇宙飞船仪表盘，就偏离了方向；它应该像一位熟练工匠的工作台。

### 可访问性说明
虽然我们使用细微的色调变化，但始终要确保 `on_surface` 文本与 `surface_container` 的对比度至少达到 4.5:1。图标使用 `outline` (#87736D)，确保它们在暖色背景上足够清晰。
